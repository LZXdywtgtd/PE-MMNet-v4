# 团队协作训练指南

> PE-MMNet v4 配置驱动的团队任务分发系统

---

## 一、系统概述

`team_train.py` 是一个配置驱动的团队任务分发系统，让团队成员无需了解复杂的命令行参数即可参与训练。

### 核心功能

| 功能 | 说明 |
|------|------|
| **配置驱动** | 任务由 JSON 配置文件定义，协调者分发 |
| **依赖管理** | 前置任务未完成自动锁定 |
| **硬件感知** | 检测 GPU 显存，自动判断任务适配性 |
| **状态可视化** | 已完成/可执行/警告/锁定 颜色区分 |
| **检查点导入** | 支持导入队友的检查点文件 |
| **自动批量执行** | 按拓扑排序执行所有可执行任务 |

---

## 二、快速开始

### 2.1 组员端操作

1. **接收配置文件**：将协调者发来的 `tasks/` 文件夹放入 `project_v4/` 目录

2. **运行脚本**：
```bash
python team_train.py
```

3. **选择任务**：输入任务编号，按回车即可开始训练

### 2.2 界面说明

### 2.3 状态标记

| 标记 | 含义 | 操作 |
|------|------|------|
| `OK` | 已完成（检查点已存在） | 自动跳过 |
| `>` | 可执行（依赖满足+硬件适配） | 直接运行 |
| `!` | 硬件警告（显存可能不足） | 需确认后运行 |
| `X` | 依赖未完成（前置任务未跑） | 需先完成依赖 |

## 三、协调者端操作

### 3.1 任务配置文件格式

在 `tasks/` 目录下创建 JSON 文件：

**普通任务** (`tasks/*.json`)：
```json
[
  {
    "id": "TASK_001",
    "name": "任务名称",
    "desc": "简短描述",
    "args": "--variant resnet18 --epochs 150",
    "level": "L1",
    "time": "~12小时",
    "gpu_mem": "~2GB",
    "deps": []
  }
]
```

**批量任务** (`tasks/batch_*.json`)：
```json
{
  "id": "BATCH_001",
  "name": "批量任务名称",
  "desc": "包含多个子任务",
  "tasks": ["TASK_001", "TASK_002"]
}
```

### 3.2 字段说明

| 字段 | 必须 | 说明 |
|------|------|------|
| `id` | 是 | 唯一标识，用于依赖引用 |
| `name` | 是 | 显示名称 |
| `desc` | 是 | 简短描述 |
| `args` | 是 | 命令行参数 |
| `level` | 是 | 性能等级：L1/L1+/L2/L2+/L3 |
| `time` | 是 | 预计时间 |
| `gpu_mem` | 是 | 预估显存 |
| `deps` | 否 | 前置依赖任务 ID 列表 |

### 3.3 硬件等级

| 等级 | 显存要求 | 说明 |
|------|----------|------|
| L1 | ~2GB | ResNet18 基线 |
| L1+ | ~4GB | YOLO 系列 |
| L2 | ~4-5GB | 带优化的变体 |
| L2+ | ~2-4GB | 分阶段训练等 |
| L3 | ~6GB | 完整优化，大图 |

### 3.4 分发任务

1. 在 `tasks/` 目录创建配置文件
2. 将整个 `tasks/` 文件夹打包
3. 发送给组员
4. 组员解压到 `project_v4/` 根目录即可

## 四、检查点导入

### 4.1 自动导入

将队友分享的 `.pt` 检查点文件复制到 `checkpoints/` 目录，下次运行 `team_train.py` 时会自动识别。

### 4.2 手动导入

运行 `team_train.py`，选择 `[i]` 导入队友检查点，输入队友的检查点文件夹路径即可。

### 4.3 注意事项

- 检查点文件命名规则：`*_{task_id}_*_best.pt`
- 如果检查点包含元数据（task_id），会优先使用元数据识别
- 否则通过文件名匹配任务 ID

---

## 五、批量执行

### 5.1 自动执行

选择 `[a]` 可以自动执行所有可执行任务（按拓扑排序）。

### 5.2 流程

1. 检测所有 `>` 和 `!` 状态的任务
2. 按依赖顺序排序
3. 依次执行，遇到失败可选择继续或停止

## 七、故障排除

### Q: 任务显示 `X` 但依赖已完成？

检查 `checkpoints/` 目录下是否有对应的检查点文件。

### Q: 硬件等级显示不正确？

确保 CUDA 驱动正常，显存计算可能包含其他进程占用。

### Q: 导入的检查点没有自动识别？

检查文件名是否包含任务 ID，或检查点是否包含 `task_id` 元数据。
