# 团队协作训练指南

> PE-MMNet v4 配置驱动的团队任务分发系统

---

## 一、系统概述

`team_train.py` 是一个配置驱动的团队任务分发系统，让团队成员无需了解复杂的命令行参数即可参与训练。

### 核心功能

| 功能 | 说明 |
|------|------|
| **配置驱动** | 任务由 JSON 配置文件定义，协调者分发 |
| **依赖管理** | 前置任务未完成自动锁定，拓扑排序执行 |
| **硬件感知** | 检测 GPU 显存，自动判断任务适配性 |
| **状态可视化** | 已完成/可执行/警告/锁定 颜色区分 |
| **检查点导入** | 支持导入队友的检查点文件 |
| **自动批量执行** | 按拓扑排序执行所有可执行任务 |
| **任务日志** | 记录每个任务的执行情况 |

---

## 二、快速开始

### 2.1 组员端操作

1. **接收配置文件**：将协调者发来的 `tasks/` 文件夹放入 `project_v4/` 目录

2. **运行脚本**：
```bash
python team_train.py
```

3. **选择任务**：输入任务编号，按回车即可开始训练

### 2.2 命令行模式

```bash
# 自动执行所有可执行任务
python team_train.py --auto

# 强制执行（包括硬件警告任务，无需确认）
python team_train.py --auto --force

# 导入队友检查点
python team_train.py --import
```

### 2.3 界面说明

```

======================================================================

当前硬件等级: L2 (显存: 6.2GB)
已完成任务: 0/9

状态标记: [✓] 已完成 | [▶] 可执行 | [!] 硬件警告 | [🔒] 依赖未完成

  [1] ▶ Swin-YOLO基线
      推荐！网格回归，适合空间定位

  [2] 🔒 门控融合优化
      依赖: BASELINE_1
      📊 L2 | ⏱️ ~10小时 | 💾 ~2GB

  [q] 退出
```

### 2.4 状态标记

| 标记 | 含义 | 操作 |
|------|------|------|
| `✓` | 已完成（检查点已存在） | 自动跳过 |
| `▶` | 可执行（依赖满足+硬件适配） | 直接运行 |
| `!` | 硬件警告（显存可能不足） | 需确认后运行 |
| `🔒` | 依赖未完成（前置任务未跑） | 需先完成依赖 |

## 三、协调者端操作

### 3.1 创建任务配置

在 `tasks/` 目录下创建 JSON 文件：

**示例：`tasks/team_baseline.json`**
```json
[
  {
    "id": "BASELINE_1",
    "name": "ResNet18基线",
    "desc": "轻量骨干，适合快速验证",
    "args": "--variant resnet18 --epochs 150",
    "level": "L1",
    "time": "~8小时",
    "gpu_mem": "~2GB",
    "deps": []
  },
  {
    "id": "BASELINE_2",
    "name": "Swin-YOLO基线",
    "desc": "推荐！网格回归，适合空间定位",
    "args": "--variant swin_yolo --epochs 150 --lr 1e-4 --batch_size 4",
    "level": "L1+",
    "time": "~8-9小时",
    "gpu_mem": "~4GB",
    "deps": []
  },
  {
    "id": "BASELINE_3",
    "name": "ViT-YOLO基线",
    "desc": "ViT风格注意力",
    "args": "--variant vit_yolo --epochs 150 --lr 1e-4 --batch_size 4",
    "level": "L1",
    "time": "~8小时",
    "gpu_mem": "~3GB",
    "deps": []
  },
  {
    "id": "BASELINE_4",
    "name": "DETR基线",
    "desc": "Transformer风格，全局上下文感知",
    "args": "--variant detr --epochs 150 --lr 1e-4 --batch_size 4",
    "level": "L2",
    "time": "~9-10小时",
    "gpu_mem": "~5GB",
    "deps": []
  }
]
```

**带依赖的任务：`tasks/team_optimization.json`**
```json
[
  {
    "id": "OPT_GATED",
    "name": "门控融合优化",
    "desc": "基于ResNet18测试门控融合",
    "args": "--variant resnet18 --fusion gated --epochs 150",
    "level": "L2",
    "time": "~10小时",
    "gpu_mem": "~2GB",
    "deps": ["BASELINE_1"]
  },
  {
    "id": "OPT_COORD",
    "name": "坐标注意力优化",
    "desc": "基于Swin-YOLO测试坐标注意力",
    "args": "--variant swin_yolo --use_coord_attn --epochs 150",
    "level": "L2",
    "time": "~10小时",
    "gpu_mem": "~4GB",
    "deps": ["BASELINE_2"]
  }
]
```

### 3.2 字段说明

| 字段 | 必须 | 说明 |
|------|------|------|
| `id` | 是 | 唯一标识，用于依赖引用 |
| `name` | 是 | 显示名称 |
| `desc` | 是 | 简短描述 |
| `args` | 是 | 命令行参数（对应 run_train.py） |
| `level` | 是 | 性能等级：L1/L1+/L2/L2+/L3 |
| `time` | 是 | 预计时间 |
| `gpu_mem` | 是 | 预估显存 |
| `deps` | 否 | 前置依赖任务 ID 列表 |

### 3.3 硬件等级

| 等级 | 显存要求 | 说明 |
|------|----------|------|
| L1 | ~2GB | ResNet18 基线 |
| L1+ | ~3-4GB | YOLO 系列 |
| L2 | ~4-5GB | 带优化的变体 |
| L2+ | ~2-4GB | 分阶段训练等 |
| L3 | ~6GB+ | 完整优化，大图 |

### 3.4 分发任务

1. 在 `tasks/` 目录创建配置文件
2. 将整个 `tasks/` 文件夹打包
3. 发送给组员
4. 组员解压到 `project_v4/` 根目录即可

## 四、检查点导入

### 4.1 自动导入

将队友分享的 `.pt` 检查点文件复制到 `checkpoints/` 目录，下次运行 `team_train.py` 时会自动识别。

### 4.2 手动导入

运行 `team_train.py`，选择 `[i]` 导入队友检查点，输入队友的检查点文件夹路径即可。

### 4.3 任务ID识别

系统通过两种方式识别检查点对应的任务：

1. **元数据读取**（优先）：从检查点的 `task_id` 字段读取
2. **文件名解析**（备用）：从文件名中提取任务ID

支持的文件名格式：
- `checkpoint_BASELINE_1_best.pt`
- `BASELINE_2_model_best.pt`
- `resnet18_BASELINE_1_best.pt`

## 五、自动执行模式

### 5.1 自动执行

```bash
python team_train.py --auto
```

按依赖顺序自动执行所有可执行任务。

### 5.2 强制执行

```bash
python team_train.py --auto --force
```

强制执行所有任务（包括硬件警告任务），无需用户确认。

### 5.3 流程

1. 检测所有可执行状态的任务
2. 按依赖顺序排序
3. 依次执行，遇到失败可选择继续或停止

## 六、任务执行日志

### 6.1 日志位置

`logs/team_training.log`

### 6.2 日志格式

```json
{"timestamp": "2026-08-05T14:32:00", "task_id": "BASELINE_1", "status": "completed", "duration_seconds": 43200, "hostname": "DESKTOP-ABC123"}
{"timestamp": "2026-08-05T15:30:00", "task_id": "BASELINE_2", "status": "failed", "error": "CUDA OOM", "hostname": "DESKTOP-ABC123"}
{"timestamp": "2026-08-05T16:00:00", "task_id": "OPT_GATED", "status": "skipped", "error": "用户取消", "hostname": "DESKTOP-ABC123"}
```

### 6.3 状态类型

| 状态 | 说明 |
|------|------|
| `started` | 任务开始执行 |
| `completed` | 任务成功完成 |
| `failed` | 任务执行失败 |
| `skipped` | 任务被跳过 |

## 七、故障排除

### Q: 任务显示 🔒 但依赖已完成？

检查 `checkpoints/` 目录下是否有对应的检查点文件，以及文件名是否包含任务 ID。

### Q: 硬件等级显示不正确？

确保 CUDA 驱动正常，显存计算可能包含其他进程占用。

### Q: 导入的检查点没有自动识别？

检查文件名是否包含任务 ID，或检查点是否包含 `task_id` 元数据。

### Q: 训练中途想跳过？

在自动执行模式下，输入 `n` 可以跳过当前失败任务继续下一个。
