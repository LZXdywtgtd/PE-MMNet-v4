## 2. 算法设计原理

### 2.1 1D 与 2D 双分支设计依据

本系统采用非对称双分支架构，分别处理时序和空间信息：

**1D 分支（时序特征提取）**

- **输入**：300点温度时序（10Hz × 30s 高频采样）
- **设计依据**：热传导遵循傅里叶定律，温度随时间的变化包含裂纹萌生的"驱动力"信息
- **网络结构**：
  - Micro 1D-CNN（kernel=3, dilation=1）：捕捉瞬态温度跳变（高频成分）
  - Macro 1D-CNN（kernel=7, dilation=3）：提取长程热耗散趋势（低频成分）
  - 双分支并行 → Concat → LayerNorm → MultiHead Self-Attention → GlobalAvgPool
- **输出维度**：64维特征向量

**2D 分支（空间特征提取）**

- **输入**：256×256 双通道图像（温度场 + 应力场）
- **设计依据**：裂纹萌生位置由应力集中决定，空间图像直接反映"薄弱位置"
- **网络结构**：ResNet-18 预训练骨干（ImageNet权重适配2通道输入）
- **输出维度**：512维特征向量

### 2.2 Cross-Attention 物理耦合机制

传统的特征融合方式（拼接、加法）无法捕捉模态间的动态关联。本系统采用双向交叉注意力实现"时域驱动力 × 空间薄弱位置"的物理耦合：

```
方向1（图像查询温度）：attn_2d→1d = softmax(Q_2d · K_1d^T / √d_k) · V_1d
  → 温度场中哪个位置对应高温/低温梯度？（驱动力识别）

方向2（温度查询图像）：attn_1d→2d = softmax(Q_1d · K_2d^T / √d_k) · V_2d
  → 温度变化应该关注图像中的哪个空间区域？（薄弱位置定位）

融合：Cross-Attention 内部完成残差连接和 LayerNorm，最后拼接两个方向的输出
  → concat([fused_2d, fused_1d]) = concat([feat_2d + attn_2d→1d, feat_1d + attn_1d→2d]) → 576维 (512+64)
```

**物理意义**：
- 温度时序的急剧变化（热冲击）驱动裂纹萌生
- 空间图像中的应力集中区是裂纹扩展的"薄弱位置"
- Cross-Attention 使模型能够根据时域变化动态关注空间特征

### 2.3 复合损失函数设计

总损失函数：
```
L_total = λ_mse · L_mse_density + λ_mono · L_mono + λ_loc · L_loc + λ_conf · L_conf
```

| 损失分量 | 物理原理 | 默认权重 |
|----------|----------|----------|
| **L_mse_density** | 直接惩罚密度预测误差 | λ_mse = 1.0 |
| **L_mono** | 格里菲斯断裂准则：裂纹密度随热应力增加不可逆递增 | λ_mono = 0.1 |
| **L_loc** | DIoU Loss：定位裂纹边界框 [x, y, l, w] | λ_loc = 1.0 |
| **L_conf** | BCE Loss：判断裂纹是否存在（density > 0.5 → 存在） | λ_conf = 1.0 |

**单调性损失设计**：
```
L_mono = Σ max(0, pred[i+1] - pred[i]) / (n-1)
```
仅当密度下降（违反单调性）时计算惩罚，物理自洽性强。

### 2.4 数据在网络内部的完整变换

本节详细追踪一个样本从输入到输出的完整数据变换过程。

#### 2.4.1 输入规格

| 模态 | 形状 | 数据类型 | 来源 |
|------|------|----------|------|
| x_1d | (300,) | float32 | Table_Temp.csv 经插值重采样 |
| x_2d | (2, 256, 256) | float32 | 温度场 + 应力场 PNG 经预处理 |

#### 2.4.2 完整前向传播路径

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                            输入层 (batch=1)                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│  x_1d: torch.Size([1, 300])           x_2d: torch.Size([1, 2, 256, 256])    │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                    ┌───────────────┴───────────────┐
                    ↓                               ↓
┌───────────────────────────────┐   ┌───────────────────────────────────────┐
│     1D 分支：TemporalFeatureExtractor                                   │
├───────────────────────────────┤   │     2D 分支：ResNet18Backbone2D        │
├───────────────────────────────┤   ├───────────────────────────────────────┤
│ Micro1DCNN:                   │   │ conv1: (2,64,k=7,s=2,p=3)             │
│   Conv1d(1→32, k=3, d=1)      │   │   → (batch, 64, 128, 128)            │
│   → (batch, 32, 300)          │   │ bn1 → relu → maxpool                 │
│                               │   │   → (batch, 64, 64, 64)               │
│ Macro1DCNN:                   │   ├───────────────────────────────────────┤
│   Conv1d(1→32, k=7, d=3)      │   │ layer1: (64→64) × 2                   │
│   → (batch, 32, 300)          │   │   → (batch, 64, 64, 64)               │
│                               │   ├───────────────────────────────────────┤
│ Concat → (batch, 64, 300)     │   │ layer2: (64→128) × 2 + downsample     │
│                               │   │   → (batch, 128, 32, 32)              │
│ 1×1 Conv → (batch, 64, 300)   │   ├───────────────────────────────────────┤
│ LayerNorm → (batch, 64, 300)  │   │ layer3: (128→256) × 2 + downsample    │
│                               │   │   → (batch, 256, 16, 16)              │
│ MultiHead Self-Attention      │   ├───────────────────────────────────────┤
│   (4 heads, dk=16)            │   │ layer4: (256→512) × 2 + downsample    │
│   → (batch, 64, 300)          │   │   → (batch, 512, 8, 8)                │
│                               │   ├───────────────────────────────────────┤
│ GlobalAvgPool → (batch, 64)   │   │ AdaptiveAvgPool → (batch, 512)        │
│         ↓                     │   │         ↓                             │
│     feat_1d                   │   │       feat_2d                         │
└───────────────────────────────┘   └───────────────────────────────────────┘
                    │                               │
                    └───────────────┬───────────────┘
                                    ↓
┌─────────────────────────────────────────────────────────────────────────────┐
│                         CrossAttentionFusion                                │
├─────────────────────────────────────────────────────────────────────────────┤
│ 输入: feat_1d (1, 64), feat_2d (1, 512)                                     │
│                                                                             │
│ 方向1：图像查询温度 (feat_2d → Q, feat_1d → K/V)                            │
│   Q_2d = Linear(512→512) → (1, 512)                                        │
│   K_1d = Linear(64→512)  → (1, 512)                                        │
│   V_1d = Linear(64→512)  → (1, 512)                                        │
│   attn_2d→1d = softmax(Q_2d @ K_1d^T / √128) @ V_1d → (1, 512)             │
│   fused_2d = LayerNorm(feat_2d + attn_2d→1d) → (1, 512)  [残差连接]         │
│                                                                             │
│ 方向2：温度查询图像 (feat_1d → Q, feat_2d → K/V)                            │
│   Q_1d = Linear(64→64)   → (1, 64)                                         │
│   K_2d = Linear(512→64)  → (1, 64)                                         │
│   V_2d = Linear(512→64)  → (1, 64)                                         │
│   attn_1d→2d = softmax(Q_1d @ K_2d^T / √16) @ V_2d → (1, 64)              │
│   fused_1d = LayerNorm(feat_1d + attn_1d→2d) → (1, 64)   [残差连接]         │
│                                                                             │
│ 融合: concat([fused_2d, fused_1d]) → (1, 512 + 64) = (1, 576)              │
│       ↓                                                                     │
│       Linear(576→576) → 最终融合特征                                        │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ↓
┌─────────────────────────────────────────────────────────────────────────────┐
│                            MultiTaskHead                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│ 输入: fused = CrossAttention([feat_2d, feat_1d]) → (1, 576)                │
│                                                                             │
│ MLP结构:                                                                     │
│   Linear(576→256) → ReLU → Dropout(0.2)                                    │
│       ↓                                                                     │
│   Linear(256→6)                                                             │
│       ↓                                                                     │
│   [x, y, l, w] → ReLU（确保非负）                                            │
│   [confidence, density] → Sigmoid（映射到[0,1]）                             │
│                                                                             │
│ 输出: torch.Size([1, 6])                                                    │
└─────────────────────────────────────────────────────────────────────────────┘
```

| 层级 | 操作 | 输入形状 | 输出形状 |
|------|------|----------|----------|
| **1D分支** | | | |
| | Micro1DCNN | (1, 1, 300) | (1, 32, 300) |
| | Macro1DCNN | (1, 1, 300) | (1, 32, 300) |
| | Concat | (1, 64, 300) | (1, 64, 300) |
| | Self-Attention | (1, 64, 300) | (1, 64, 300) |

| | conv1 + pool | (1, 2, 256, 256) | (1, 64, 64, 64) |
| | layer1 | (1, 64, 64, 64) | (1, 64, 64, 64) |
| | layer2 | (1, 64, 64, 64) | (1, 128, 32, 32) |
| | layer3 | (1, 128, 32, 32) | (1, 256, 16, 16) |
| | layer4 | (1, 256, 16, 16) | (1, 512, 8, 8) |

#### 2.4.4 输出解析

模型输出 `[x, y, l, w, confidence, density]` 各维度的含义和范围：

| 索引 | 名称 | 激活函数 | 输出范围 | 物理意义 |
|------|------|----------|----------|----------|
| 0 | x | ReLU | [0, +∞) | 裂纹中心 X 坐标（归一化） |
| 1 | y | ReLU | [0, +∞) | 裂纹中心 Y 坐标（归一化） |
| 2 | l | ReLU | [0, +∞) | 裂纹长度（归一化） |
| 3 | w | ReLU | [0, +∞) | 裂纹宽度（归一化） |
| 4 | confidence | Sigmoid | [0, 1] | 裂纹存在置信度 |
| 5 | density | Sigmoid | [0, 1] | 裂纹密度（物理量） |

**注意**：坐标归一化基于物理尺寸 0.02m × 0.015m，输出值需乘以对应尺寸才是真实坐标。

## 3. 多模态数据构建

### 3.1 331 组样本来源

| 数据批次 | 样本数 | 仿真参数 | 说明 |
|----------|--------|----------|------|
| 单次扫描 | 21 | 固定参数 | 0~1s（步长0.05s） |
| 参数化扫描1 | 155 | 5 h_ceramic × 31 时间步 | 不同冷风强度 |
| 参数化扫描2 | 155 | 同上 | 额外参数化数据 |
| **总计** | **331** | - | - |

**训练/测试划分**：统一随机80/20划分
- 训练集：264样本
- 测试集：67样本

### 3.2 1D 序列插值

原始探针数据：706点（微小时步，约3E-8s间隔）

处理流程：
1. 按 h_ceramic 分组，提取每个参数下的时间序列
2. 对齐到21个参考时间点（与图像匹配）
3. 取3个探针点温度均值
4. 使用 `scipy.interpolate.interp1d(..., fill_value="extrapolate")` 重采样到300点

### 3.3 2D 图像预处理

**跨批次色标差异问题**：
- 不同批次数据的颜色映射（Colormap）可能不同
- 直接使用原始像素值会导致跨批次训练不稳定

**解决方案：Max-Min 归一化 + Center Crop**

```
原始PNG (640×480, RGB)
       │
       ▼ [灰度转换]
灰度图 (640×480)
       │
       ▼ [Max-Min归一化 → 0~1]
消除色标差异
       │
       ▼ [Center Crop 70%]
聚焦物理区域（10mm×10mm）
       │
       ▼ [Resize 256×256]
2×256×256 Tensor
```

### 3.4 物理安全数据增强

**设计原则**：允许模拟传感器误差，禁止破坏物理边界条件

**绝对禁止的增强**：
| 增强方式 | 禁止原因 |
|----------|----------|
| 水平/垂直翻转 | 温度场/应力场有物理方向性 |
| 随机旋转 | 裂纹萌生位置有方向偏好 |
| 随机裁剪/缩放 | 改变温度梯度的空间分布 |

**允许的增强**：
| 增强方式 | 物理意义 |
|----------|----------|
| GaussianNoise(std=0.01) | 模拟热电偶测量噪声 |
| BrightnessContrast(±5%) | 模拟光照变化 |
| TimeMasking(5%) | 模拟数据采集瞬时缺失 |

## 4. 训练策略

### 4.0 时间偏移预测（Predict Offset）

v4 版本新增了时间偏移预测功能，允许模型学习预测未来时刻的裂纹状态。

#### 4.0.1 功能说明

| 参数 | 说明 |
|------|------|
| `--predict_offset 0` | 默认模式，输入 t 时刻数据，预测 t 时刻标签 |
| `--predict_offset 1` | 输入 t 时刻数据，预测 t+0.05s 的标签 |
| `--predict_offset 2` | 输入 t 时刻数据，预测 t+0.1s 的标签 |

#### 4.0.2 使用场景

- **裂纹预警**：提前 0.05s/0.1s 知道裂纹将出现在哪个位置
- **趋势预测**：预测裂纹密度的增长趋势

#### 4.0.3 技术实现

时间偏移在数据加载层实现：
- `SingleBatchDataset.__getitem__` 中，标签索引使用 `target_idx = sample_idx + predict_offset`
- `MultiBatchCollateDataset` 自动过滤越界样本（最后 N 个样本）

#### 4.0.4 使用命令

```bash
# 预测 0.05s 后的裂纹状态
python run_train.py --mode train --predict_offset 1

# 预测 0.1s 后的裂纹状态
python run_train.py --mode train --predict_offset 2

# 评估时间偏移训练的模型
python run_train.py --mode eval --checkpoint ./checkpoints/xxx.pt --predict_offset 1
```

**注意**：训练和评估必须使用相同的 `--predict_offset` 值，确保数据一致性。

### 4.1 优化器与学习率

```python
optimizer = AdamW(lr=3e-4, weight_decay=0.01)
scheduler = CosineAnnealingLR(T_max=150, eta_min=1e-6)
```

**参数选择依据**：
- AdamW：结合了Adam自适应学习率和Weight Decay正则化
- 3e-4：BERT/ResNet等预训练模型微调的经典学习率
- CosineAnnealing：学习率余弦衰减，末期接近0，有利于收敛到最优解

### 4.2 早停机制

```python
patience = 20  # 连续20个epoch验证损失不下降则停止
min_delta = 1e-4  # 改善阈值
```

**参数选择依据**：
- patience=20：足够观察学习率衰减周期，避免过早停止
- min_delta=1e-4：区分真实改善与随机波动

### 4.3 损失函数权重分配

| 参数 | 值 | 设计考量 |
|------|-----|----------|
| λ_mse | 1.0 | 主任务，密度预测精度 |
| λ_mono | 0.1 | 物理约束，权重较低避免过度约束（实验表明λ_mono=0.1时物理违反率仍达51.5%） |
| λ_loc | 1.0 | 定位任务，与MSE同等重要 |
| λ_conf | 1.0 | 分类任务，裂纹存在判断 |

## 5. 消融实验定量分析

### 5.1 实验配置

| 配置项 | 值 |
|--------|-----|
| 训练轮数 | 150 epochs |
| 批次大小 | 8 |
| 学习率 | 3e-4 |
| Dropout | 0.2 |
| 早停patience | 20 |
| 训练时间 | 约243分钟 |

### 5.2 实验结果

| 变体 | R² | RMSE | MAE | mIoU | 违反率 |
|------|-----|------|-----|------|--------|
| 仅时序分支 (1D Only) | 0.0374 | 0.2165 | 0.0961 | 0.5540 | 34.8% |
| 仅空间分支 (2D Only) | 0.9456 | 0.0515 | 0.0386 | 0.5886 | 50.0% |
| 双分支+拼接 (Concat) | 0.9401 | 0.0540 | 0.0382 | 0.5875 | 50.0% |
| 双分支+加法 (Add) | 0.9595 | 0.0444 | 0.0339 | 0.6096 | 50.0% |
| Cross-Attention (无mono) | 0.9687 | 0.0390 | 0.0298 | 0.6103 | 54.5% |
| 完整MM-DBFNet (λ_mono=0.1) | 0.9440 | 0.0522 | 0.0461 | 0.5807 | 51.5% |

### 5.3 核心结论

**结论1：空间分支绝对主导（空间信息 > 时序信息）**

- 仅2D分支 R²=0.9456 vs 仅1D分支 R²=0.0374
- 空间图像直接反映应力分布，是裂纹定位的决定性因素
- 1D时序单独使用几乎无法预测裂纹（R²≈0）

**结论2：Cross-Attention 在大样本下优势显著**

- Cross-Attention (R²=0.9687) > 双分支+加法 (R²=0.9595) > 双分支+拼接 (R²=0.9401)
- 交叉注意力机制有效捕捉"时域驱动力 × 空间薄弱位置"的耦合关系
- mIoU=0.6103，为所有变体最高

**结论3：物理约束（λ_mono=0.1）与精度的博弈关系**

- 无mono约束：违反率54.5%，但R²=0.9687（最高）
- 有mono约束（λ_mono=0.1）：违反率51.5%，R²=0.9440
- λ_mono增大导致精度下降，但物理违反率仅略有改善（3%）
- **建议**：若追求最高精度可禁用mono；若需物理自洽可保持λ_mono=0.1（权衡有限）
