## 2. 损失函数权重详解

### 2.1 默认权重配置

```python
# training/mono_loss.py - MultimodalCrackLoss.__init__
MultimodalCrackLoss(
    lambda_mse_density=1.0,  # MSE密度损失权重
    lambda_mono=0.1,          # 单调性损失权重
    lambda_loc=1.0,           # 定位损失权重
    lambda_conf=1.0           # 置信度损失权重
)
```

### 2.2 各权重的物理含义

| 权重 | 物理意义 | 默认值 | 调大效果 | 调小效果 |
|------|----------|--------|----------|----------|
| **λ_mse** | 直接优化密度预测精度 | 1.0 | 密度更准 | 密度更差 |
| **λ_mono** | 物理单调性约束（裂纹不可逆） | 0.1 | 物理自洽性↑，但精度可能↓ | 精度↑，物理违反率↑ |
| **λ_loc** | 边界框定位精度 | 1.0 | 位置更准 | 位置更差 |
| **λ_conf** | 裂纹存在判断 | 1.0 | 置信度更准 | 置信度更差 |

### 2.3 为什么 λ_mono 默认只有 0.1？

**设计考量**：
1. 物理约束是"软约束"：单调性是物理规律，但不是损失函数的主要目标
2. 实验验证：λ_mono=0.1 时违反率仍达51.5%，说明单调性约束需要与其他任务竞争
3. 过大的 λ_mono 会导致模型过度关注单调性而牺牲密度预测精度

**调大 λ_mono 会怎样？**
- 物理违反率降低（单调性更严格）
- 但 R² 也会下降（精度损失）
- 极端情况：λ_mono=1.0 可能导致模型"死板"地单调递增，失去预测灵活性

### 2.4 场景化调参指南

根据实际问题选择调整策略：

**场景A：mIoU 很低（位置预测差）**

```bash
# 增加定位损失权重
python run_train.py --mode train --variant full \
    --epochs 150 \
    --lambda_loc 2.0  # 或更高
```

**场景B：密度预测不准（R² 低）**

```bash
# 增加MSE密度损失权重
python run_train.py --mode train --variant full \
    --epochs 150 \
    --lambda_mse 2.0
```

**场景C：物理违反率高（密度下降）**

```bash
# 增加单调性损失权重
python run_train.py --mode train --variant full \
    --epochs 150 \
    --lambda_mono 0.5  # 注意：这可能导致精度下降
```

**场景D：综合调参（推荐渐进式）**

```bash
# 1. 先用默认配置观察baseline
python run_train.py --mode train --variant full --epochs 150

# 2. 根据评估结果针对性调整
# 如果R²>0.9但违反率>60% → 调高lambda_mono
# 如果R²<0.8 → 调高lambda_mse

# 3. 微调示例
python run_train.py --mode train --variant full \
    --lambda_mse 1.5 --lambda_mono 0.2
```

### 2.5 分割任务损失函数（v4.1.0 新增）

使用 `--task segmentation` 或 `--task multitask` 时，系统使用不同的损失函数。

#### 2.5.1 SegmentationLoss

```python
# training/mono_loss.py - SegmentationLoss
SegmentationLoss(
    lambda_dice=1.0,   # Dice Loss 权重
    lambda_bce=0.5     # BCE Loss 权重
)
```

**损失公式**：
```
L_total = λ_dice * L_dice + λ_bce * L_bce
```

#### 2.5.2 各权重的物理含义

| 权重 | 物理意义 | 默认值 | 调大效果 | 调小效果 |
|------|----------|--------|----------|----------|
| **λ_dice** | Dice系数（重叠度） | 1.0 | 更关注整体重叠 | 可能忽略细节 |
| **λ_bce** | 像素级交叉熵 | 0.5 | 更关注每个像素的准确性 | 可能忽略整体结构 |

#### 2.5.3 为什么分割损失权重不同？

**Dice Loss 的优势**：
- 对类别不平衡更鲁棒（裂纹区域通常只占图像的 5-20%）
- 直接优化 IoU 指标
- 训练更稳定

**BCE Loss 的优势**：
- 像素级精确优化
- 梯度更细粒度

**默认值 λ_dice=1.0, λ_bce=0.5**：
- 优先保证 Dice 系数（整体重叠）
- BCE 作为辅助（细节优化）

#### 2.5.4 分割任务调参场景

**场景A：Dice 系数低（掩膜重叠差）**
```bash
# 增加 Dice Loss 权重
python run_train.py --mode train --task segmentation \
    --epochs 100
# 在 training/mono_loss.py 中修改：
# SegmentationLoss(lambda_dice=2.0, lambda_bce=0.5)
```

**场景B：掩膜边缘模糊**
```bash
# 增加 BCE Loss 权重
python run_train.py --mode train --task segmentation \
    --epochs 100
# 在 training/mono_loss.py 中修改：
# SegmentationLoss(lambda_dice=1.0, lambda_bce=1.0)
```

#### 2.5.5 多任务损失（Multitask）

```python
# training/mono_loss.py - MultimodalSegmentationLoss
MultimodalSegmentationLoss(
    lambda_seg=1.0,   # 分割损失权重
    lambda_det=0.5    # 检测损失权重
)
```

**损失公式**：
```
L_total = λ_seg * L_seg + λ_det * L_det
```

**默认 λ_seg=1.0, λ_det=0.5**：
- 分割任务权重更高（像素级任务更精细）
- 检测任务作为辅助（边界框信息）

**调整策略**：
- 如果只需要精确的分割掩膜 → 增大 λ_seg
- 如果同时需要检测框 → 适当增大 λ_det
- 建议保持 λ_seg > λ_det（分割精度更重要）

## 3. 图像预处理详解

### 3.1 完整预处理流程

```python
# data/dataset_multimodal.py - ImagePreprocessor

PNG (640×480, RGB)
       │
       ▼ [灰度转换]  RGB → 灰度
灰度图 (640×480)
       │
       ▼ [Max-Min归一化]  每张图独立归一化到0~1
归一化图 (0~1)
       │
       ▼ [Center Crop 70%]  裁剪中心区域
裁剪图 (448×336)
       │
       ▼ [Resize 256×256]  双线性插值
256×256 灰度Tensor
       │
       ▼ [通道拼接]  温度场 + 应力场
2×256×256 Tensor
```

### 3.2 为什么必须 Max-Min 归一化？

**问题**：不同批次数据的颜色映射（Colormap）不同

```
单次扫描：可能使用 "hot" 映射 → 范围 [0, 2000]
参数化扫描：可能使用 "jet" 映射 → 范围 [0, 1800]
```

如果直接使用原始像素值：
- 同一温度在不同批次可能显示为不同像素值
- 模型需要学习批次无关的特征

**Max-Min 归一化公式**：
```
normalized = (pixel - min) / (max - min)
```

**效果**：
- 无论原始色标如何，归一化后值域统一为 [0, 1]
- 模型只需学习温度/应力的相对分布，不受绝对值影响

### 3.3 为什么必须 Center Crop？

**问题**：图像边缘存在大量留白（物理区域仅占中心10mm×10mm）

**解决方案**：70% Center Crop
```
原始图像: 640×480
裁剪后:   448×336 (70%)
调整后:   256×256
```

**物理意义**：
- 去除边缘留白，聚焦实际物理区域
- 减少模型学习"无关背景"的机会
- 加快训练收敛

### 3.4 预处理代码示例

```python
from data.dataset_multimodal import ImagePreprocessor

preprocessor = ImagePreprocessor(
    image_size=256,
    crop_ratio=0.70
)

# 使用示例
from PIL import Image
img = Image.open("温度01.png")
tensor = preprocessor(img)  # 返回 torch.Tensor [1, 256, 256]
```

## 4. 物理安全数据增强

### 4.1 增强策略对比

| 增强方式 | 物理安全性 | 说明 |
|----------|------------|------|
| 随机旋转 | ❌ 禁止 | 破坏温度梯度的方向性 |
| 水平/垂直翻转 | ❌ 禁止 | 破坏应力分布的方向性 |
| 随机裁剪 | ❌ 禁止 | 改变温度梯度的空间分布 |
| 随机缩放 | ❌ 禁止 | 改变物理尺寸的尺度 |
| 高斯噪声 | ✅ 允许 | 模拟传感器测量误差 |
| 亮度调整 | ✅ 允许 | 模拟光照变化（不影响物理） |
| 对比度调整 | ✅ 允许 | 模拟成像条件变化 |

### 4.2 禁止增强的物理原因

**旋转/翻转禁止**：
```
物理背景：热应力分布有明确的方向性
- 冷风从左侧吹入 → 左侧温度更低，应力更大
- 翻转后：模型会学习到"错误的温度-应力对应关系"
```

**裁剪/缩放禁止**：
```
物理背景：温度梯度的空间分布是裂纹定位的关键
- 裁剪会移除部分温度场信息
- 缩放会改变温度梯度的相对位置
```

### 4.3 允许增强的物理意义

**高斯噪声 (std=0.01)**：
```
模拟热电偶测量噪声
- 真实传感器有约1%的测量误差
- 噪声增强使模型更鲁棒
```

**亮度/对比度调整 (±5%)**：
```
模拟光照变化
- 相机曝光不同导致图像整体明暗变化
- 物理量（温度/应力）本身不变
- 归一化后的图像值受影响
```

### 4.4 增强代码示例

```python
from data.dataset_multimodal import PhysicalSafeTransform2D

# 启用物理安全增强
transform = PhysicalSafeTransform2D(
    noise_std=0.01,      # 高斯噪声
    brightness=0.05,     # 亮度调整
    contrast=0.05,       # 对比度调整
    enabled=True
)

# 使用
img_tensor = transform(img_tensor)
```

## 5. 早停与过拟合防范

### 5.1 早停机制原理

```python
# run_train.py - 训练配置
config = {
    'patience': 20,      # 连续20个epoch验证损失不下降则停止
    'min_delta': 1e-4,   # 改善阈值
}
```

**工作流程**：
```
for epoch in range(150):
    train_loss = train_one_epoch()
    val_loss = validate()

    if val_loss < best_loss - min_delta:
        best_loss = val_loss
        patience_counter = 0
        save_checkpoint()
    else:
        patience_counter += 1

    if patience_counter >= patience:
        print("Early stopping!")
        break
```

### 5.2 patience=20 的设定依据

| patience值 | 效果 |
|------------|------|
| 5 | 过早停止，可能欠拟合 |
| 10 | 适中，但可能错过最优解 |
| **20** | **推荐：足够观察学习率衰减周期（CosineAnnealing）** |
| 30+ | 过晚停止，可能过拟合 |

**设计原理**：
- CosineAnnealingLR 的周期约为 50-100 epochs
- patience=20 允许模型至少观察 1/3 个周期
- 避免因短期波动而过早停止

### 5.3 模型过早停止时的干预策略

**症状**：patience=20 内停止，但指标（R²、mIoU）不理想

**干预策略A：降低学习率**
```bash
python run_train.py --mode train --variant full \
    --lr 1e-4  # 从3e-4降到1e-4
```

**干预策略B：增加 patience**
```bash
python run_train.py --mode train --variant full \
    --patience 40  # 给模型更多时间
```

**干预策略C：调整 Dropout**
```bash
python run_train.py --mode train --variant full \
    --dropout 0.3  # 增加正则化，减少过拟合风险
```

**干预策略D：检查数据问题**
```python
# 检查数据是否有异常
from data.dataset_multimodal import create_multibatch_dataloaders
train_loader, test_loader = create_multibatch_dataloaders(
    data_roots=[...], batch_size=8, augment=False
)

for (seq_1d, img_2d), labels in train_loader:
    print(f"Labels: min={labels.min():.4f}, max={labels.max():.4f}")
    print(f"Density: min={labels[:,5].min():.4f}, max={labels[:,5].max():.4f}")
    break
```

### 5.4 过拟合防范清单

| 检查项 | 方法 |
|--------|------|
| 训练/测试损失差距 | 训练损失低但测试损失高 → 过拟合 |
| 验证集指标 | mIoU/R² 持续下降 → 过拟合 |
| 单调性违反率 | 测试集违反率远高于训练集 → 过拟合 |

**缓解措施**：
1. 增加 Dropout（0.2 → 0.3）
2. 增加 weight_decay（0.01 → 0.02）
3. 减少模型复杂度（使用轻量版）
4. 增加数据增强强度

### 6.3 故障排查

#### 检测任务问题

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| Loss = NaN | 学习率过高 | 降低 --lr |
| 过早停止 | patience过小 | 增加 --patience |
| mIoU很低 | 定位损失不足 | 调高 --lambda_loc |
| 违反率>80% | 单调性约束不足 | 调高 --lambda_mono |

#### 分割任务问题

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| Dice < 0.3 | 模型未收敛 | 增加训练轮数 |
| 掩膜全黑/全白 | 学习率过高或数据问题 | 降低 --lr，检查标签 |
| 掩膜边缘模糊 | BCE权重过低 | 增加 λ_bce |
